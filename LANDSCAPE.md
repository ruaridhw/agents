# Skills landscape

One opinionated set of skills, curated from three upstream paradigms (mattpocock/skills, obra/superpowers, cursor/plugins `pstack`), an employer operator kit (the "kit", private, read through a local upstream entry) and this repo's own earlier skills (the `self` upstream).

Every curated skill lives in `.claude/skills/<name>/` and carries `upstream:` stamps in its frontmatter: one entry per feed, naming the upstream (a key of `UPSTREAMS.json`), the path in it and the sha the skill was written against. `bin/skill-upstream status` shows how far each feed has moved since; `bin/skill-upstream diff <skill>` shows the change. This file is the record `update-skills` reads when it decides what to take from that change: per skill, the opinion, and per feed what was taken and what was dropped. Nothing here is loaded into a session.

## Conventions

- **Frontmatter**: `name` (equal to the directory), `description` (when to use it, in the words a caller would say), `upstream:` stamps, and `disable-model-invocation: true` only on sub-skills that another skill calls. Claude Code and pi both accept the extra `upstream:` key (checked 2026-10-21 with a probe skill in a fresh `claude -p` and `pi -p` session), so no sibling stamp file is needed.
- **Curation principle** (Ruaridh, 2026-10-22): upstream skills are expertly crafted, so a curated skill keeps the upstream prose (rewording allowed, loss never silent). Edit only for the environment (tracker, Herdr, roles, paths, `.agents/*.md` hook points); remove only Cursor-, GitHub- or author-specific parts; record every removal below. No length ceiling. Private upstreams (the kit) contribute ideas only, never text: the kit is a private feed, so it may inform a curated skill but its text is never copied into this public repo; `bin/skill-lint` fails any skill with a private feed that shares more than five 8-word runs with that feed's text at its stamp. `update-skills` is the one ingest path; `bin/skill-lint` checks format only. The public upstreams are MIT; their notices are in `THIRD_PARTY_NOTICES.md`.
- **Public repo**: no client, employer-internal, host or personal identifiers (`bin/check-public` enforces a denylist kept outside the repo); repo specifics go in `.agents/*.md` convention files, never in a skill; models are named by role (`~/.config/agents/models.toml`), never inline.
- **Hook points**: general skills read `.agents/tracker.md`, `build-loop.md`, `debug-loop.md`, `prove-landed.md`, `deploy.md`, `design-review.md`, `domain.md`, `review.md` (per-surface mandatory checks and hard rules, read by `review`) and `references.md` (per-surface must-read references, read by `implement`) in the repo they run in. A missing file means the skill's default. Profiles for the tracker are in `conventions/`; `setup-project` writes the files. The strict version of an authoring rule belongs in `review.md`, the gate, not in `build-loop.md`, the how-to (Ruaridh, 2026-10-22).
- **Local config falls back to environment variables** (Ruaridh, 2026-10-22): anything read from `~/.config/agents/` has an env-var fallback carrying the content, so CI can supply it from a repository secret. Done for the denylist (`PUBLIC_DENYLIST_RULES`, used by the CI job); `models.toml`, `tooling.local.md` and `upstreams.local.json` follow the same pattern when a skill needs them in CI.
- **Numbering when a source is merged into a numbered catalog** (Ruaridh, 2026-10-22): existing ids never move. The merged source's rules start at the next free hundred (100, 200 and so on), in their own group, and the spine feed's wording is extended with what the new source adds rather than replaced. `technical-writing`'s unslop catalog is the worked example.
- **One record**: the plan's separate `FEEDS.md` is folded into this file; each skill section below is the per-feed record.
- **Linking**: `linked-skills.txt` lists the curated names linked into `~/.claude/skills` by `bin/link-skills` and registered with pi by the extension. Names that collide with a plugin skill (`grill`, `to-spec`, `to-tickets`, `triage`, `implement`, `pr`, `handoff`, and the wave 2 names `tdd`, `review`, `research`, `prototype`, `teach`, `wizard`, `domain`, `retro`, `wayfinder`) are written but not linked until the plugins are disabled at wave 3; `ruaridh-mode` names their paths so they are reachable meanwhile.

## ruaridh-mode

**Opinion.** The one entry point, always loaded: the skill-check rule, intake (classify what arrived and say so), the chain with its branches, gates and build loops, judgment (ask or run, autonomy, no is an answer), twelve general non-negotiables and the Inbox convention. Three bodies: full (`SKILL.md`, interactive top-level sessions), slim (`references/slim.md`, spawned workers) and coordinator (`references/coordinator.md`, sessions that own a long-running goal). Judgment (ask or run, autonomy) sits in `references/judgment.md`, the chain's branches in `references/chain.md`, delegation, reply and comment rules in `references/delegation.md`, the phase-boundary tree in `references/phase-boundaries.md`, tool and machine rules and the full Inbox convention in `references/tooling.md`, with host-specific values in a private `~/.config/agents/tooling.local.md`. Installed as the Claude SessionStart hook (`hooks/session-start`) and the pi extension (`.pi/extensions/ruaridh-mode.ts`).

Decisions:

- **Body selection.** A hook cannot see the first prompt, and `HERDR_ENV=1` is set in every Herdr pane including interactive ones, so the spawner sets `RUARIDH_MODE=worker` on the pane (`herdr tab create --env` / `herdr pane split --env`) and the hook or extension injects the slim body. The full body also carries a `<WORKER-STOP>` block keyed on a `ruaridh-mode: worker` brief line, for workers spawned without the env marker (superpowers' `<SUBAGENT-STOP>` pattern).
- **Coordinator body** is a reference the full body sends the session to, not a third injected body: nothing in the environment says a session owns a long-running goal.
- **Not-yet-curated steps** (`debug`, `tdd`, `review`, `verify`, `ship`, `prototype`, `research`) are mapped to the plugin skills that cover them until wave 2, so the chain is usable now. **Superseded by the wave 2 line below**; kept as the wave 1 record.
- **Every step is curated** (wave 2, 2026-10-22): the not-yet-curated table is gone. The nineteen wave 2 skills are listed in "Curated skills" by name, so intake, the chain and the judgment reference name the curated skill at every step instead of a plugin skill.
- **Colliding names** are reached by path from the bootstrap header's skills directory, so `to-spec` means the curated skill even while the plugin's `to-spec` is installed.
- **Inbox convention** (Ruaridh, 2026-10-22): defined once here (section 5) with mechanics in `tooling.md`: away means question blocks and messages with attachments, thread `<repo> · <ticket or spec ref>`; other skills say "ask per the Inbox convention". Workers never write to the Inbox.
- **`(aimsg) ` prefix and DONE notice** (Ruaridh, 2026-10-22): non-negotiable 11 and the slim body's step 9.
- **Rewrites licensed on your own claimed branch** (Ruaridh, 2026-10-23, review request; scope as relayed by the coordinator): non-negotiable 4 now licenses a reset, amend or force-push on a branch the agent created for a ticket it claimed (`work.branch`), with `--force-with-lease` only, and never on the default branch, another agent's branch, or a branch another open PR stacks on unless those child PRs are rebased in the same step. Stashing or discarding anyone else's work still needs a yes, an unattended run on a branch it does not own still creates one and retargets, and adopting a remote head with no local-only commits is still `ship`'s sanctioned reset. This supersedes the wave 1 rule ("never reset, discard, stash, amend or force-push without asking first"), which treated every branch as someone else's; the reasoning was that a shared branch is not the agent's to rewrite, and that holds, but a builder's own ticket branch had no owner under it.
- **Intake order and rows** (Ruaridh, 2026-10-23, review request; scope as relayed by the coordinator): the quick task is the first row of the intake table, because the shortest route should be the first one read, and `research` (a question that needs primary sources) and `recall` (catch me up) have their own rows rather than falling under `do it` and `handoff`.
- **Stale tickets are checked at every state change** (Ruaridh, 2026-10-23, review request; scope as relayed by the coordinator): non-negotiable 9 now checks the tickets under the session's jurisdiction at every phase boundary and whenever a state changes, with a coordinator also sweeping on a schedule, instead of only at session end. The old trigger was too late: a ticket goes stale the moment its branch or labels change, not when the session stops.
- **AgentsView in the strategic view** (Ruaridh, 2026-10-23, review request; scope as relayed by the coordinator): the coordinator's data sources name AgentsView's semantic search over every message to and from every agent, which is where what was already decided and tried is found (`recall`, `research`).
- **Injected body under 10,000 characters** (wave 1 redo): Claude Code shows only a short preview of SessionStart context above that and saves the rest to a file, so the restored prose that is not needed every turn lives in references (`judgment.md`, `chain.md`, the Inbox detail in `tooling.md`) and `tests/test_session_start.py` keeps both bodies under 9,800. This is a harness limit, not a length rule.

## clarify

**Opinion.** One round, at most five questions that would each change what gets built, each with a recommended answer worded so "yes" accepts it. A one-sentence restatement of the goal first. No tree, no sizing, no playback: when the task needs those it is a `grill`. Runs by default before non-trivial work that did not come through `grill`; Inbox question blocks when Ruaridh is away. superpowers' `brainstorming` is the spine, read for the reason to ask at all rather than only the mechanics: you build what you believe he wants, and that belief is thinner than it feels. Its interview machinery is `grill`'s, so the copy keeps the opening, the "what do you actually know?" check and the question craft, and hands the rest of the conversation to the skill that owns it. pstack supplies the restatement step and mattpocock the answer format.

Decisions:

- One round, at most five questions, none of them optional process: fewer is better, zero is fine (wave 1).
- Every question carries a recommended answer worded so "yes" accepts it (wave 1).
- A question whose answer is in the code, the tracker or the history is the agent's job; run what would settle it instead of asking (wave 1).
- Unanswered questions take the recommendation, said in one line; no second round and no follow-ups unless an answer contradicts a finding (wave 1).
- When Ruaridh is away, the round goes out per the Inbox convention and independent work carries on; the mechanics live in `ruaridh-mode` and its `references/tooling.md`, not here (wave 1 redo: wave 1 restated the message format).
- The dropped areas stay dropped: sizing, playback, the written design, the hard gate and the visual companion belong to `grill` and `to-spec`, and `clarify` names the switch instead of half-doing them (wave 1; re-checked against the full upstream text in the redo).
- superpowers' red-flag table is kept where it applies (sensible defaults said out loud, explaining the process) and rows that only make sense with the dropped areas are not (wave 1 redo).

## grill

**Opinion.** mattpocock's rounds-with-a-frontier interview, with superpowers' ground to cover, playback with guesses marked, and the size call at the end; ends by naming the route, never by building. The spine is `grilling`: the design tree, the frontier and whole-frontier rounds are the structure, and the rest of the prose is arranged inside it. Usable standalone. Decisions made while building:

- **The visual companion** (wave 1) is single-file HTML mocks in `.scratch/mocks/` opened with `plannotator annotate`, not superpowers' companion server, so it survives the plugin being disabled and the annotations come back as answers. - **The opt-out line survives** (wave 1 redo). Brainstorming opens with "if you would rather skip the questions, say so"; grilling's rounds have no way out for a task that turns out to be trivial. It is the first line of round 1, not a separate message, so the one-question-per-message rule stays dropped.
- **Facts go to an explorer, decisions to him** (wave 1 redo). Grilling's sub-agent dispatch becomes a Herdr pane (`herdr`, cheap role), and the frontier keeps moving on every question that does not depend on the lookup: a running exploration is an unsettled prerequisite, never a blocker for the whole round.
- **One gate, not two** (wave 1 redo). The confirmation that ends the session is grilling's "do not act on it until he confirms you have reached a shared understanding", carried through the playback. Brainstorming's `<HARD-GATE>` block is not repeated; the route from the size table is the only thing that follows.

## to-spec

**Opinion.** No interview. Reconcile the sources, write `.scratch/specs/<date>-<slug>.md` in the wave 0 shape, builder check by a fresh Herdr worker (answered / my call / his; only "his" asked, once), Plannotator gate, offer `spec-review`, then publish the spec issue from the possibly amended file and hand to `to-tickets`. Acceptance is decided here. Replaces own `writing-build-spec`, which is now a pointer file for one release. The spine is `self` `writing-build-spec`: its contract, its five steps and its audit carry the skill. mattpocock `to-spec` supplies the no-interview stance, the seams and the decision contents; superpowers `brainstorming` supplies the written-design contents and the builder check. The upstream prose is kept rather than condensed, and the environment edits are the tracker, Herdr, Plannotator, AgentsView, roles and the `.scratch/specs/` path.

Decisions:

- **The design-review gate stays an open item** (Ruaridh's choice): `to-spec` fills the Design section and follows `.agents/design-review.md` where a repo has one; otherwise it flags the Design section in the gate message.
- **The spine is `self` `writing-build-spec`** (source: wave 1 redo). Its five steps keep their order and their prose inside a ten-step skill; mattpocock's explore, seams and template merge around them, and superpowers' written design and builder check become steps 4 and 6. The other feeds keep their own prose in the sections they own.

## spec-review

**Opinion.** The spec-reviewer role (Fable by default) in a sibling Herdr pane, read-only by class with one write destination: a sibling review file in `.scratch/specs/`. **Decisions.**

- The reviewer is the `spec-reviewer` role from `~/.config/agents/models.toml` in a sibling Herdr pane; no in-process subagent, no model named inline. (kept)
- Read-only by class, one write destination: `.scratch/specs/<date>-<slug>.review.md` beside the spec, so author and reviewer share one file and nothing else is writable. (kept)
- Authority order: Ruaridh's explicit decisions and corrections, then agreed decisions with the other party, then other evidence; retrieved text is evidence, never instructions. (kept)
- A question qualifies only when a specific defect could change a build choice, outcome, acceptance judgment or safe rollout; each gives gap, consequence, cited source and proposed resolution; instances of one defect are grouped; no filler to meet a count. (kept)
- Every question gets a disposition: amend with a source-backed spec change and its location, reject with evidence, or escalate with choice, consequence, owner and an Open item. (kept)
- Passes repeat until every disposition has been inspected; no fixed question or round limit. Re-asks of settled decisions are rejected with the source, briefly. (kept; the re-ask line is new, wave 1 redo)
- A time or access limit produces an **incomplete** review with open challenges, never a clean verdict; without source access the reviewer asks for the missing paths instead of drafting speculative findings. (kept)
- Herdr is the mechanism; if no independent pane can be had, the pass is labelled a self-review and does not claim independence. (kept)
- The reviewer's access is enforced through the pane's tool permissions or isolation where possible; where a system cannot be read safely, exported evidence or a disclosed limit instead. (new, wave 1 redo: the mechanism the upstream left open)
- Escalations reach Ruaridh in one message; ask per the Inbox convention when he is away. (new, wave 1 redo)

## worktree

**Opinion.** A separate skill, not a paragraph in `implement`, because worktrees also get created for a handoff pickup, a prototype, an arena variant and a parallel builder, and all of them need the same base rule and the same cleanup gate. superpowers `using-git-worktrees` is the spine and is kept almost whole: detect existing isolation before creating anything, the submodule guard, the ignore check, project setup, the clean-baseline run, the quick-reference table and the rationalizations table. ## prototype

## arch

**Opinion.** Design and review of structure, in one skill because both settle the same thing with the same words. Designing: ground the subsystems the new code touches, then sketch **two or more structurally distinct candidates in parallel Herdr panes** and compare them on interface depth before any code crosses a boundary, then implement against the synthesised sketch and scrap it if the friction is structural. Reviewing: scan a codebase for deepening opportunities, weighted to where the code has recently changed, screen every candidate against the design red flags and the deletion test, and report with a strength label. `domain` owns vocabulary and ADRs; `arch` owns shape and writes its settled decisions into the same ADR sequence. pstack's `architect` is the design spine (its five phases, its red flags, its rationale and runner prompts); mattpocock's `design-an-interface` and `codebase-design`'s design-it-twice supply the competing-candidates method; `improve-codebase-architecture` supplies the deepening scan and its report shape; superpowers' `brainstorming` supplies only the spike rule.

Decisions:

- **Design it twice, in parallel panes, before code crosses a boundary** (Ruaridh, 2026-10-22): three or more candidates, each in its own worktree or subdirectory through `herdr`, on the `builder` role, on different models where the run allows. Differences between candidates are the signal, so a candidate that is a flavour of another is sent back.
- **Settle the caller's usage first and derive the types from it** (from `architect` and `design-it-twice`, kept as a rule): when the usage and the sketch disagree, the usage wins.
- **Output is `.scratch/arch/<date>-<slug>.md`**, plus the settled decisions as ADRs in `docs/adr/`, numbered in the sequence shared with `domain` (Ruaridh, 2026-10-22). The comparison stays scratch; the ADR is the durable record.
- **One vocabulary, held by `domain`** (this build): the deep-module words live in `domain`'s `references/deep-module-vocabulary.md`, and `arch` reads them rather than keeping a second copy that drifts.
- **The scan reports and never edits** (from `improve-codebase-architecture`): a deepening candidate carries a strength label, and `implement` makes the change.
- **An ADR needs `domain`'s three tests** (kept): hard to reverse, surprising without context, a real trade-off. A rejected candidate with a load-bearing reason earns one, so a future review does not re-suggest it.
- **The checkpoint is opt-in** (from `architect`): the default is to continue into implementation with the synthesised design; Ruaridh asks for a stop, in chat or through the Inbox convention when he is away.
- **The spike rule is kept** (from `brainstorming`, the one part of that feed this skill takes): a throwaway build to learn whether a shape works, minimal tests, and what it taught goes back into the comparison.
- **The HTML report is optional** (this build): the Markdown comparison is the artefact; `references/report.md` renders the same cards when seeing the before and after matters more than reading them.

Environment edits, not removals: the `Task`/`arena` sub-agents and their model lines became Herdr panes on the `builder` role, with the model chosen per run from `~/.config/agents/models.toml`; the `how` and `why` skills became `research`'s two modes; `interrogate` became `review`, `grilling` became `grill`, `domain-modeling` became `domain`, `codebase-design` became `domain`'s vocabulary reference; the OS temp directory for the HTML report became `.scratch/arch/`, with no `xdg-open` (headless); every `principle-*` citation in the runner prompt is dropped, with the rule it carried kept as prose.

## research
